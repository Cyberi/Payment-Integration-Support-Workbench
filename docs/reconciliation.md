# Reconciliation (diagnostic only)

**This is a diagnostic tool that runs on synthetic data. It is not connected to any real settlement process.**

## Input
A CSV with exactly these columns: `provider_reference, merchant_reference, transaction_date, amount, currency, status, refunded_amount`.
- `amount` is an integer in `currency` (`IRR` or `IRT`). It is converted to IRR with the exact helper; a non-exact value is a row error.
- `status` is `SUCCEEDED`, `FAILED` or `EXPIRED`.
- Up to 1 MB and 5,000 rows. Any bad row rejects the whole file and reports row numbers.

## Exception types
| Type | Rule | What the tool suggests |
|---|---|---|
| `duplicate_provider_reference` | The same `provider_reference` appears twice. The second row is flagged; nothing is deleted. | Ask the provider to confirm the single settlement or send a corrected report. |
| `provider_only` | The provider has a row with no internal payment (by reference, or by `merchant_reference` with no provider reference). | Search by `merchant_reference`; ask the provider for transaction details. |
| `amount_mismatch` | Converted amount differs from the internal amount. | Check the adapter unit and the sent amount; verify against the contract. |
| `status_mismatch` | Provider status is not compatible with the internal status. | Run verify; check for a missing or rejected webhook. |
| `internal_only` | An internal succeeded payment in the report date range is missing from the report. | Compare report dates (Tehran time) and payment time; check whether it belongs to the next period. |

Every exception has a `suggestion` and a `verification` step. Exceptions can be linked to a case, or resolved with a note of at least 10 characters. Resolving does not change money.

## What the tool never does
- Delete a row or a payment.
- Change an amount, a status or an order.
- Mark a settlement as final.

## Demo data
`data/examples/provider-transactions-demo.csv` is generated by `scripts/seed_demo_data.py` from the seeded simulator ledger, then changed on purpose to include one example of each exception type. The file header is the real report format; nothing in it is a real transaction.

**Important:** the demo CSV matches the database right after `python -m scripts.reset_demo_data`. Scenario runs done later add payments that are not in the CSV, so they show up as `internal_only`. Reset before a clean demo.
