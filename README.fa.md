# آزمایشگاه تمرین پرونده‌های پشتیبانی نرم‌افزار

یک پروژه کوچک و محلی برای تمرین بررسی پرونده‌های Application Support با چند رخداد ساختگی مرتبط با پرداخت. رابط برنامه فارسی و راست‌به‌چپ است و کد با کتابخانه استاندارد پایتون اجرا می‌شود.

> **فقط شبیه‌سازی است.** این برنامه به بانک، پرداخت‌یار یا درگاه واقعی متصل نمی‌شود و هیچ اطلاعات واقعی مشتری یا تراکنشی ندارد. داده‌های رخداد ثابت و ساختگی‌اند. برنامه فقط یادداشت‌های تحلیل‌گر و وضعیت پرونده را در SQLite محلی ذخیره می‌کند.

[English README](README.md) · [چک‌لیست بررسی پرونده](docs/incident-handling-fa.md)

## چه چیزی را تمرین می‌کند؟

- بازنویسی دقیق گزارش کاربر و پیدا کردن شناسه‌های سفارش، پرداخت و هم‌بستگی.
- مقایسه وضعیت داخلی با شواهد ارائه‌دهنده و رویدادهای webhook بدون فرض اینکه یک منبع همیشه درست است.
- ثبت یادداشت بررسی و جمع‌بندی مبتنی بر شواهد.
- جلوگیری از حل پرونده پیش از ثبت یادداشت بررسی و جلوگیری از یادداشت‌گذاری مجدد روی پرونده حل‌شده.
- استفاده از پرس‌وجوهای پارامتری SQLite و escape کردن متن پویا هنگام ساخت HTML.
- اجرای یک برنامه کوچک پایتون و تست‌های آن بدون نصب کتابخانه جانبی در زمان اجرا.

## پرونده‌های تمرینی

۱. پرداخت در سامانه داخلی pending است، اما شواهد ساختگی ارائه‌دهنده succeeded را نشان می‌دهد و webhook پیدا نشده است.

۲. یک رویداد webhook دوبار دریافت شده؛ در شواهد نمونه، دریافت دوم duplicate ثبت شده است.

۳. مبلغ گزارش تطبیق با رکورد داخلی سازگار به نظر نمی‌رسد و واحد ردیف گزارش معلوم نیست. اقدام ایمن، بررسی واحد و منبع داده است، نه ویرایش مبلغ.

این پرونده‌ها عمداً محدود نگه داشته شده‌اند. برنامه موتور پرداخت نیست و تمام قواعد واقعی ارائه‌دهندگان را شبیه‌سازی نمی‌کند.

## پیش‌نیاز

- Python نسخه 3.11 یا بالاتر
- بدون وابستگی به کتابخانه‌های ثالث در زمان اجرا

## اجرا

در پوشه پروژه اجرا کن:

~~~bash
python -m support_lab --reset
~~~

سپس در مرورگر به نشانی http://127.0.0.1:8000 برو. برنامه فقط روی loopback اجرا می‌شود و برای دسترسی از شبکه محلی یا اینترنت طراحی نشده است. برای توقف، Ctrl+C را بزن.

تنظیم اختیاری پورت و مسیر پایگاه داده:

~~~powershell
$env:SUPPORT_LAB_PORT = "8010"
$env:SUPPORT_LAB_DB = "var/my-practice.sqlite3"
python -m support_lab
~~~

~~~bash
SUPPORT_LAB_PORT=8010 SUPPORT_LAB_DB=var/my-practice.sqlite3 python -m support_lab
~~~

گزینه --reset پایگاه داده آزمایشی انتخاب‌شده را حذف و سه پرونده نمونه را دوباره ایجاد می‌کند. روی پایگاه داده‌ای که به اطلاعاتش نیاز داری از این گزینه استفاده نکن.

## اجرای تست‌ها

~~~bash
python -m unittest discover -s tests -v
~~~

تست‌ها ایجاد داده نمونه، ذخیره یادداشت، قواعد شروع بررسی و حل پرونده، محدودیت پرونده حل‌شده و escape شدن متن HTML را بررسی می‌کنند. عبور تست‌ها به معنی آماده‌بودن برای استفاده عملیاتی نیست.

## محدودیت‌ها

- ورود کاربر، نقش‌ها، CSRF، نگهداری ممیزی در سطح سازمانی، آزمون هم‌زمانی، پایش عملیاتی و اتصال واقعی پرداخت وجود ندارد.
- داده‌های آزمایشی ثابت‌اند و نشان نمی‌دهند بانک یا پرداخت‌یار واقعی چنین رفتاری داشته است.
- این پروژه تمرین آموزشی و نمونه‌کار است، نه مدرک تجربه حرفه‌ای کار با سامانه مالی.
- استفاده از ابزارهای هوش مصنوعی را شفاف بیان کن و قبل از معرفی پروژه در مصاحبه، مطمئن شو تمام بخش‌هایی را که به آن‌ها استناد می‌کنی، واقعاً می‌فهمی و می‌توانی توضیح بدهی. تجربه عملیاتی یا تخصصی فراتر از دامنه این پروژه ادعا نکن.
